# pm-loop:本项目代码优化循环

一个循环 = **检查 → 裁决 → 修复 → 验收 → 复盘** 五步,一步都不能少。
目的:把「用户用出来才发现的问题」变成「agent 扫出来的问题」,每轮结束时仓库处于
已提交、已推送、生产可用、复盘已归档的状态。

这套流程来自 2026-10 对刷题网页(quiz/)的一轮实战:四路并发审计出 23 条发现,
前端/后端并行修完、双人复核 diff、副本库验收,全程生产库零污染。

## 项目结构真相(动手前先确认没漂移)

- 前端:`quiz/app.js`(~950 行,单文件 SPA)+ `quiz/style.css` + `quiz/index.html`
- 后端:`src/quiz_web.py`(标准库 HTTP server,`--db db/quiz.sqlite --port 8765`)
- 出题管线:`src/quiz_gen.py`;口径真相:`src/quiz_schema.sql` 注释 + `AGENTS.md`
- 数据库 `db/quiz.sqlite` 是**唯一真相来源**:永远不拿它当测试对象,测试一律用副本
- 网页静态文件每次请求从磁盘读(`Cache-Control: no-store`),改前端**免重启**;
  改 `quiz_web.py` 需重启服务(`pkill -f "quiz_web[.]py"` 方括号防连坐,再 nohup 拉起)

## 第 1 步:检查 —— 并发审计(用一个统一视角模板)

按「视角」切分,每视角派一个 `explore` subagent,几个视角同时发。改了谁就审谁,
不必每次都四路全开;但**跨视角的交叉问题**(CSS 有类没接线、API 口径和文档不一致)
最容易漏,视角数量下限是 2。

四个标准视角(提示词骨架,按需裁剪):

1. **交互状态覆盖**(前端):交叉对比 JS/HTML 用到的所有 class 与 CSS 定义,找两类问题:
   a) JS 切了类名但 CSS 没定义(用户操作无反馈——历史上 `.picked`/`.current`/`.qno`
   三个死规则全是这类);b) CSS 定义没人用(死代码)。另查 hover/disabled/focus-visible
   完备性、ARIA。
2. **用户旅程**(PM 视角,前端):按 练习→错题本→模拟考→统计 逐流程走查:进度反馈、
   中断/退出路径、空态/边界(0题、抽卷池不足、交卷失败)、键盘与鼠标一致性、切 tab 丢状态。
   输出按 P0(挡住使用)/P1(明显别扭)/P2(锦上添花)分级。
3. **API 与数据口径**(后端):对照 AGENTS.md 与 schema 注释核查 SQL 口径、判分阈值、
   幂等/竞态(重复提交、并发写)、答案是否提前泄露、异常路径;每条写:位置/影响/修法。
4. **布局与数值**(CSS):sticky 偏移量要**推算真实高度**核对(顶栏实际高度 ≈ 89px 桌面 /
   手机折行更高)——不要相信拍脑袋的数字;响应式溢出、对比度(WCAG)、色觉冗余编码。

对 subagent 的通用要求:输出「文件:行号、问题、严重度、一句话修法」清单,中文,
要精确不要泛泛,不许贴大段代码。

## 第 2 步:裁决 —— 排序,砍过度工程

- 排序标准:**用户会不会撞到**(P0)、**统计/判分可信度**(P0)、明显别扭(P1)、锦上添花(P2)。
- 主动砍掉:修了会引入复杂度的小瑕疵、和本产品定位不符的"企业级"方案。
- 产出两份清单:「本轮修」+「backlog」,backlog 按价值排序,写进 `PLAN.md` 留给下轮。
- 一轮修多少?上一轮的标准:一个 P0 + 所有"用户点了没反应"级的一批,宁多勿拖;
  大结构改造(如断点续考)单独立项,不塞进常规轮。

## 第 3 步:修复 —— 并行但要隔离

- **前端主会话修,后端派 general subagent(或反过来)**:不同文件、互不碰,
  最后分别 commit。给 subagent 的指令必须包含:改动粒度、风格(简洁中文注释)、
  验收方式、以及红线(**绝对不许写 db/quiz.sqlite**,测试用 /tmp/opencode/ 下的副本)。
- 已踩过的坑,修的时候顺手防再犯:
  - 写死偏移量 → 收敛成单一来源(如 `--tb` 变量,boot() 用 JS 实测顶栏高度注入 CSS),
    关联值(exam-head 的 top 与 exam-q 的 scroll-margin)必须一起改;
  - JS 切类名前,先对照第 1 步的状态矩阵确认 CSS 已接上;
  - 键盘事件:焦点落在按钮内要防 document 级 keydown 双触发;
  - 异步渲染:await 回来先检查 `state.tab` 还是不是本页,防止旧响应覆盖新页面;
  - 写库路径:answer/submit 这类 POST 必须考虑幂等与并发,`BEGIN IMMEDIATE` + rowcount 判定。

## 第 4 步:验收 —— 生产零污染

1. 静态检查:`node --check quiz/app.js`;`python3 -m py_compile src/quiz_web.py`;
   CSS 查花括号配平、不留垃圾文本。
2. 生效验证:`curl http://127.0.0.1:8765/app.js | grep 改动标记`(前端免重启);
   后端改完重启服务,`curl /api/meta /api/stats` 只读冒烟。
3. 行为级测试:在 **/tmp/opencode/** 建副本库 + 临时测试脚本(import 模块直测),
   覆盖本次改的每条路径幂等/竞态/口径;测试完留在 /tmp/opencode,不进 git。
4. 人工复核:subagent 的 diff 要亲自读一遍再提交(`git diff`),重点看它有没有
   顺手改不该改的东西。
5. 提交拆逻辑单元,fix/perf/docs 分开;commit message 带「改了什么/为什么/验收结果」;push。

## 第 5 步:复盘 —— 归档病根,不是归档现象

- 给用户汇报定式:①模块走读表(模块=产品职责=发现=修法,√ 标注);②反思
  (为什么这类问题会漏,归到病根,如「写了=做了」「魔法数字各自为政」「只测 happy path」);
  ③backlog 更新 + 下一轮输入。
- 病根记进本 skill(往「坑清单」追加),让下一轮在检查阶段就防住,而不是靠记性。
- `PLAN.md` 的 backlog 区同步追加,用户下次说「再跑一个循环」时从 backlog 顶端继续。

## 触发与续跑

用户说「再跑一个循环 / 再来一轮 / 继续优化」→ 直接从 `PLAN.md` backlog 顶端取任务,
跳过第 1 步的全量审计,只对该模块做定向检查(单视角也行),其余步骤照走。
用户新鲜报的 bug = 下一轮输入的最高优先级,先单点复修,再考虑并入循环。
