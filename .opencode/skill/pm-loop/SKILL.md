# pm-loop:代码价值分析 + 循环优化

一个循环 = **走读 → 审计 → 裁决 → 修复 → 验收 → 复盘** 六步,一步都不能少。
两条主线都要有:①**每段代码的实际作用与价值**(是什么、有没有真在起作用、值多少);
②**用户/数据的缺口**(哪里没反馈、哪里口径错了)。只有①容易变成知识梳理,只有②容易
漏掉"这个模块根本不该存在"级别的结论。每轮结束时:仓库已提交已推送、生产可用、
盘点和病根已归档。

## 走读的判断纪律(来自实战教训)

- **价值要用证据,不用感觉**:每段先答三个问题——被谁调用(grep 出调用点)、
  影响哪个用户场景、删掉会发生什么。答不出来的就是【存疑】。
- **"写了 = 做了"是本会话踩过的最大坑**:JS 切了 `.picked`/`.current`/`.qno` 类名而
  CSS 没接上,三处"看似在起作用"的代码实际作用为零。判断实际作用必须连到链路终点
  (用户看得到什么变化),不是看代码"逻辑上存在"。
- **魔法数字 / 拍脑袋常量**(74/84/96px 各自为政)价值为负:它们制造了"已对齐"的错觉。
  结论不是返工,而是收敛成单一来源。
- **只测 happy path 的分支**(交卷失败、空池、未作答)价值打折:分支存在但没人在
  真实路径上验证过,按【有用·未验证】记账,验收补测。

## 项目结构真相(动手前先确认没漂移)

- 前端:`quiz/app.js`(单文件 SPA,~950 行)+ `quiz/style.css` + `quiz/index.html`;
  模块分层:全局工具/状态 → PracticeCard(单题+键盘)→ PracticeSession(批次/进度)→
  错题本 → 模拟考(卷面/倒计时/结果回顾)→ 统计——走读按这个顺序逐段过。
- 后端:`src/quiz_web.py`(标准库 HTTP server,`--db db/quiz.sqlite --port 8765`);
  分层:middlerare SQL 口径(usable_sql/attempt_streaks/fetch_wrong_book)→ 各 API →
  HTTP 层。
- 口径真相:`src/quiz_schema.sql` 注释 + `AGENTS.md`;数据 `db/quiz.sqlite` 唯一真相,
  永不拿来测试。
- 静态文件免重启;改 `quiz_web.py` 要重启(`pkill -f "quiz_web[.]py"` 方括号防连坐)。

## 六步流程

### 1. 走读:逐段价值分析(主会话亲自做,不外包)

按模块自上而下读,输出**走读表**:每段一行
`模块/段名 | 实际作用(产品视角一句话) | 证据(调用点、用户场景) | 价值评级 | 建议`。
价值评级口径:**核心**(高频路径,不可少)/ **有用**(真实场景需要)/ **备用**(留有意义的,
注明何时启用)/ **存疑**(被谁调、删掉会怎样答不上来:死代码、过度工程、防御过度)。
每条给建议:保留 / 简化 / 合并 / 删 / 重写。这一步的产出直接喂给第 3 步裁决。

### 2. 审计:并发 subagent 找缺口(视角可裁剪,下限 2 个)

四个标准视角(explore subagent,提示词骨架):

1. **交互状态覆盖**:交叉对比 JS/HTML class 与 CSS 定义,找"有类没样式"和"有样式没类";
   另查 hover/disabled/focus-visible/ARIA 完备性。
2. **用户旅程**(PM):练习→错题本→模拟考→统计逐流程走查;进度反馈、中断/退出路径、
   空态/边界(0题、池不足、交卷失败)、键盘鼠标一致性、切 tab 丢状态。按 P0/P1/P2 分级。
3. **API 与口径**:同源 SQL 对照 AGENTS.md/schema;判分阈值、幂等、并发写、答案泄露、
   异常路径。每条:位置/影响/修法。
4. **布局数值**:sticky 偏移要**推算真实高度**核对(别信拍脑袏述);响应式溢出、对比度、
   色觉冗余编码。

外加(与第 1 步互补的机器视角):**调用关系盘点**——grep 所有 function/class/CSS
规则的使用次数,找出从未被引用、或只被一条死路径引用的"纸面存在物"。
通用要求:输出「文件:行号、问题、严重度、一句话修法」,精确不泛泛,不贴大段代码。

### 3. 裁决:排序,砍过度工程

-【存疑】代码(实际作用答不上来的)和 P0 同样要判个明白:要么删、要么接线激活,
  不允许"留着算了"。
- 排序:用户撞不撞到 → 统计可信度 → 明显别扭(P1)→ 锦上添花(P2)。
- 主动砍:修了会引入复杂度的小瑕疵、"企业级"式过度防御。
- 产出「本轮修」+「backlog」(写进 PLAN.md);大结构改造单独立项,不塞常规轮。

### 4. 修复:并行但要隔离

- 前端主会话修,后端派 general subagent(或互换);不同文件、互不碰、分开 commit。
  subagent 指令必须含:改动粒度、风格(简洁中文注释)、验收方式、红线(**绝不写
  db/quiz.sqlite**,测试用 /tmp/opencode/ 副本)。
- 踩过的坑顺手防再犯:偏移量收敛单一来源(如 `--tb` 由 boot 实测注入),关联值
  (exam-head top ↔ exam-q scroll-margin)必须同改;JS 切类先对照 CSS 状态矩阵;
  键盘焦点防 document 级双触发;异步响应回来先查 `state.tab` 防覆盖;
  POST 写库路径必须考虑幂等/并发(BEGIN IMMEDIATE + rowcount)。

### 5. 验收:生产零污染

- `node --check quiz/app.js`、`py_compile src/quiz_web.py`、CSS 花括号配平。
- 前端改完 curl 8765 对照改动标记(免重启);后端改完重启,GET 冒烟。
- 行为测试:/tmp/opencode/ 副本库 + import 模块直测幂等/竞态/口径;测试脚本留 /tmp/opencode,
  不进 git。
- subagent 的 diff 亲自读(看它有没有顺手改不该改的);commit 拆 fix/perf/docs,
  message 带「改什么/为什么/验收结果」;push。

### 6. 复盘:归档病根,不是归档现象

- 汇报定式:①走读表(各段价值√/存疑);②各缺口清单;③反思——为什么这类问题会漏,
  归到病根(「写了=做了」「魔法数字」「happy path」等),病根更新到本 skill;
  ④backlog 更新 + 下一轮输入。
- `PLAN.md` backlog 同步;下次「再跑一个循环」从 backlog 顶端取,定向审计可跳过全量。
- 用户新鲜报的 bug = 最高优先级,先单点复修再考虑并入循环。
